## 开发模型

本地开发使用一个共享 PostgreSQL 容器，并为每个 checkout 使用一个数据库。

- 主 checkout 通常使用 `.env` 和 `POSTGRES_DB=multica`
- 每个 Git worktree 使用自己的 `.env.worktree`
- 每个 checkout 都连接到同一个 PostgreSQL host：`localhost:5432`
- 隔离发生在数据库层面，而不是启动单独的 Docker Compose 项目
- 后端和前端端口仍然按 worktree 保持唯一

## 前置条件

- Node.js `v20+`
- `pnpm` `v10.28+`
- Go `v1.26+`
- Docker

## 首次设置

### 主 Checkout

```bash
cp .env.example .env
make setup-main
```

`make setup-main` 会：

- 使用 `pnpm install` 安装 JavaScript 依赖
- 确保共享 PostgreSQL 容器正在运行
- 如果应用数据库不存在，则创建它
- 对该数据库运行所有 migrations

启动应用：

```bash
make start-main
```

### Worktree

从 worktree 目录运行：

```bash
make worktree-env
make setup-worktree
```

启动 worktree 应用：

```bash
make start-worktree
```

## 日常流程

### 主 Checkout

```bash
make start-main
make stop-main
make check-main
```

### Feature Worktree

```bash
git worktree add ../multica-feature -b feat/my-change main
cd ../multica-feature
make worktree-env
make setup-worktree
make start-worktree
```

日常使用：

```bash
make start-worktree
make stop-worktree
make check-worktree
```

## 同时运行主 checkout 和 worktree

这是被一等支持的流程。两个 checkout 使用同一个 PostgreSQL 容器，但使用不同数据库和端口：

| | 主 checkout | Worktree |
|---|---|---|
| Database | `multica` | `multica_my_feature_702` |
| Backend port | `8080` | 生成值（例如 `18782`） |
| Frontend port | `3000` | 生成值（例如 `13702`） |

## 命令

```bash
# 前端（所有命令都通过 Turborepo）
pnpm install
pnpm dev:web          # Next.js dev server（端口 3000）
pnpm dev:desktop      # Electron dev（electron-vite，HMR）
pnpm build            # 构建所有前端应用
pnpm typecheck        # TypeScript 检查
pnpm lint             # ESLint
pnpm test             # TS tests（Vitest）

# 后端（Go）
make dev              # 运行 Go server（端口 8080）
make daemon           # 运行本地 daemon
make build            # 构建 server + CLI binaries
make test             # Go tests
make sqlc             # 重新生成 sqlc code
make migrate-up       # 运行数据库 migrations
make migrate-down     # 回滚 migrations
```

## 测试

运行所有本地检查：

```bash
make check
```

它会运行：

1. TypeScript typecheck
2. TypeScript unit tests
3. Go tests
4. Playwright E2E tests

## 故障排查

### 缺少环境文件

创建预期的环境文件：

```bash
# 主 checkout
cp .env.example .env

# Worktree
make worktree-env
```

### 检查 checkout 使用哪个数据库

```bash
cat .env           # 或 .env.worktree
```

查看 `POSTGRES_DB`、`DATABASE_URL`、`PORT`、`FRONTEND_PORT`。

### 列出所有本地数据库

```bash
docker compose exec -T postgres psql -U multica -d postgres \
  -At -c "select datname from pg_database order by datname;"
```

### 破坏性重置

停止 PostgreSQL 并保留本地数据库：

```bash
make db-down
```

只重置当前 checkout 的数据库（删除 `POSTGRES_DB`，重新创建，并重新运行所有 migrations）。其他 worktree 数据库不受影响。

```bash
make stop
make db-reset
make start
```

> 如果 `DATABASE_URL` 指向远程 host，`make db-reset` 会拒绝运行。

清空所有本地 PostgreSQL 数据：

```bash
docker compose down -v
```

> **警告：** 这会删除共享 Docker volume 和所有数据库。之后必须重新运行 `make setup-main` 或 `make setup-worktree`。
