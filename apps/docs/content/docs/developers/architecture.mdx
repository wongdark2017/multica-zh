## 概览

Multica 是 Go 后端 + 单仓库前端（pnpm workspaces + Turborepo），并带有共享包。

```
┌──────────────┐     ┌──────────────┐     ┌──────────────────┐
│   Next.js    │────>│  Go Backend  │────>│   PostgreSQL     │
│   Frontend   │<────│  (Chi + WS)  │<────│   (pgvector)     │
└──────────────┘     └──────┬───────┘     └──────────────────┘
                            │
                     ┌──────┴───────┐
                     │ Agent Daemon │  (在你的机器上运行)
                     │Claude/Codex/ │
                     │OpenClaw/Code │
                     └──────────────┘
```

## 项目结构

| 目录 | 用途 | 技术 |
|-----------|---------|------------|
| `server/` | Go 后端 | Chi router、用于 DB 的 sqlc、gorilla/websocket |
| `apps/web/` | Next.js 前端 | App Router |
| `apps/desktop/` | Electron 桌面应用 | electron-vite |
| `apps/docs/` | 文档站点 | Fumadocs |
| `packages/core/` | 无界面业务逻辑 | 不依赖 react-dom，可跨平台复用 |
| `packages/ui/` | 原子 UI 组件 | 无业务逻辑，基于 shadcn |
| `packages/views/` | 共享业务页面 | 不导入 next/\*，不导入 react-router |
| `packages/tsconfig/` | 共享 TypeScript 配置 | — |
| `packages/eslint-config/` | 共享 ESLint 配置 | — |

## 后端结构

- **入口点**（`cmd/`）：`server`（HTTP API）、`multica`（CLI + daemon）、`migrate`
- **Handlers**（`internal/handler/`）：每个 domain 一个文件（issue、comment、agent、auth、daemon）
- **实时通信**（`internal/realtime/`）：Hub 管理 WebSocket clients，server 广播 events
- **Auth**（`internal/auth/` + `internal/middleware/`）：JWT（HS256），middleware 设置 `X-User-ID` 和 `X-User-Email` headers
- **任务生命周期**（`internal/service/task.go`）：enqueue → claim → start → complete/fail
- **Agent SDK**（`pkg/agent/`）：通过 Claude Code 或 Codex 执行 prompts 的统一 `Backend` interface
- **Daemon**（`internal/daemon/`）：自动检测 CLIs、注册 runtimes、轮询 tasks
- **Database**：PostgreSQL 17 + pgvector，sqlc 根据 `pkg/db/queries/` 中的 SQL 生成代码

## 前端架构

### Internal Packages 模式

所有共享包都导出原始 `.ts`/`.tsx` 文件（不预编译）。消费它们的应用 bundler 会直接编译这些文件。这带来零配置 HMR 和即时 go-to-definition。

### 包边界

- `packages/core/` — 不允许 react-dom、localStorage、UI libs。所有 Zustand stores 都在这里。
- `packages/ui/` — 纯 UI components，无业务逻辑。
- `packages/views/` — 不允许 `next/*`、`react-router-dom`。使用 `NavigationAdapter` 处理路由。

### 状态管理

- **TanStack Query** 管理所有服务端状态（issues、users、workspaces）
- **Zustand** 管理所有客户端状态（UI selections、filters、drafts）
- **React Context** 仅用于跨切面管线（`WorkspaceIdProvider`、`NavigationProvider`）

### 数据流

```
Browser → ApiClient (shared/api) → REST API (Chi handlers) → sqlc queries → PostgreSQL
Browser ← WSClient (shared/api) ← WebSocket ← Hub.Broadcast() ← Handlers/TaskService
```

## Multi-tenancy

所有 queries 都按 `workspace_id` 过滤。Membership checks 控制访问。`X-Workspace-ID` header 将 requests 路由到正确 workspace。
